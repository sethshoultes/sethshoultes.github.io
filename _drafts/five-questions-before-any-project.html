--- title: "Five Questions Before Any Project" subtitle: "A short list I use to decide whether a project is worth doing at all." description: "A short list I use to decide whether a project is worth doing at all." read_time: "4 min read" ---

Most projects are easy to start and hard to judge. Someone has an idea, it sounds good, and a month later nobody can say whether it was worth it.

So before a project begins, I like to ask five plain questions. They are short on purpose.

  1. How does this help us reach a big goal? Selling more, saving time, or making an existing system or process better. If it does none of those, stop here.
  2. How much money might it bring in? A rough number is fine. A blank is a warning.
  3. How much time will it take? Yours and everyone else's.
  4. What will it need? People, tools, money, someone's attention.
  5. What do we already have that this touches, or could use? Often the best answer is already half built.

None of these needs a spreadsheet. The point is not precision. The point is to say the answers out loud before you commit, so that "this sounds good" becomes "this is worth two weeks of our time, and here is why."

Notice what is missing: nothing in the list asks how clever the idea is. Clever is cheap. What matters is whether it moves a goal you already care about.

If you are an owner, try it on the next idea someone brings you. If you cannot answer the first two questions, the idea probably is not ready yet. That is useful to know before anyone starts work.
